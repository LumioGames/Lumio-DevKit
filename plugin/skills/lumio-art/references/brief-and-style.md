# 简报、风格与协作

美术简报把玩家需要知道的事变成可以制作和检查的画面要求。

## 用挖矿场景确定目标

1. 玩家需要区分地面、墙体和可挖的矿脉。
2. 近看能辨认材质，远看仍能从主色和轮廓区分方块。
3. 挖掘成功后，地形缺口、掉落和火花应与玩法状态一致。
4. 先在真实浏览器视图检查一组方块，再批量制作。

Sample 的 [方块素材说明](https://github.com/LumioGames/LumioSample/blob/f98322c2eec8f83b5caf07aa2ad15d9c55b6f8fb/Client/Assets/Blocks/README.md) 给出了观察距离、128 像素贴图、采样与透明度要求；这是 Sample 的选择，不是所有 Lumio 游戏都必须采用的画风。

## 把需求写清

| 条件 | 需要决定什么 |
| --- | --- |
| 玩家判断 | 看见后应知道什么、采取什么动作。 |
| 场景与镜头 | 界面还是世界对象，常见距离、视口和遮挡。 |
| 状态 | 默认、可交互、等待、成功或失败中哪些需要区分。 |
| 风格依据 | 项目已有规范、同组资产与可用参考。 |
| 消费入口 | 客户端从哪里加载，支持什么格式与参数。 |
| 验收环境 | 实际浏览器、设备和对照场景。 |

已有规范就沿用；未确定的内容写成工作假设，先做不依赖它的部分。风格还没确定时比较少量方案，说明轮廓、主色、细节如何帮助玩家判断，以及修改成本。参考图只用于分析，不自动变成可分发素材。

## 先做代表样品

挑一件容易暴露问题的资产，例如顶侧底不同的草方块，或有镂空区域的玻璃。按 [资产生产](asset-production.md) 导出，在 [真实页面](integration-and-review.md) 检查远近、背景与相邻方块。先确认可读性和接入方式，再扩成整包。

UI（用户界面）图标应在实际大小检查，文字与状态提示保持可读。交互热区和图片尺寸分别记录，不能仅凭设计软件预览决定点击范围。

## 协作与交回

美术交可修改源、导出设置、状态示意和来源；客户端开发交真实加载入口、错误与页面结果；玩法开发说明状态含义和碰撞要求。一人可以承担多项工作，不需要额外设审批角色。

修改意见应包含资产版本、问题位置、出现条件和具体建议。只有概念稿就交概念稿结果；接入能力缺失时写清缺什么格式、入口或环境，继续完成可独立制作的源文件与样品。
