# 资产生产、来源与交接

适用于 UI、图标、贴图、模型源与导出物。本文目录与清单均为推荐的项目协作约定；先遵循项目现有结构，真实运行路径由消费端确定。

## 先保留可修改来源

必须能够回答：这项素材从哪里来，谁改过，哪个源导出了哪个运行文件，旧版本怎样恢复。可以用现有版本库、资产管理工具或交接记录实现，不要求每个文件名都带版本号。

建议分开保存：

```text
art/
  source/       可编辑文档、模型、分层图、矢量原稿
  exports/      按消费设置导出的候选文件
  previews/     实际大小对照图、状态图、场景截图
  provenance/   来源与许可记录、需要随包保留的署名材料
  handoffs/     版本、文件、消费端和验收记录
```

这不是 Lumio 自动扫描目录。运行资产仍放到项目构建或宿主指定的位置。手动复制时记录源与目标；已有构建脚本时让脚本复制。源文件、预览、采购凭据等不应被默认打入客户端分发包。

## 来源与许可记录

每项资产至少记录来源类型、作者或提供方、来源定位、获取版本、许可或使用授权的记录位置，以及实际使用范围。引用第三方素材时，保留其要求的署名材料；尚未确认分发范围的素材先留作参考，换成已获授权的资源再交付运行包。

| 来源 | 应保留什么 |
|---|---|
| 团队原创 | 作者、源文件版本、共同创作或外包交付约定的位置 |
| 开放素材或图标库 | 具体素材及版本、来源页、对应许可文本、修改记录 |
| 购买或委托素材 | 授权记录的位置、使用范围与交付内容；账单等私密信息不放公共包 |
| 字体 | 字体文件与版本、嵌入或分发使用依据、子集或改造记录 |
| 生成素材 | 工具与可识别版本、生成输入、参考素材来源、人工修改与使用条件记录 |

本技能的 MIT 许可不替代所用图片、字体、模型等各自的许可。参考图不因进入 mood board 就成为可随游戏分发的素材；生成结果也需要独立检查来源与使用条件。无需为记录来源而把未授权素材上传到外部服务。

## 2D UI 与图标的首件流程

1. **检查实际控件**：确认显示边界、文字、交互热区、状态和缩放。控件行为与图像视觉分别处理，避免把可点击范围误当作图片尺寸。
2. **复用同组语言**：从现有图标提取观察角度、轮廓厚薄、留白、重心和阴影习惯。先做一个基础形，与相邻图标在真实大小下并排比较。
3. **列适用状态**：默认、指向、键盘焦点、按下、禁用、选中、等待中按控件需要取用。哪些由 CSS 或控件绘制、哪些需要独立资产，交接时写清；不必每态都导出一张图。
4. **对接可用格式**：沿用已有加载器支持的格式。矢量是否原样使用、位图是否透明、动画是否可消费，都以宿主验证为准。无法确认时先交预览和源文件，导出状态写「待验证」。
5. **放回界面检查**：查看深浅背景、长文案、实际字体回退、缩放和高像素密度显示。焦点与禁用态保持可辨，装饰不遮状态文字或必要提示。

若选择位图，记录像素尺寸、透明度处理、色彩解释与缩放方式。不要把 CSS 显示尺寸与文件像素尺寸混为一项。小图缩放模糊时先比较真实显示大小和采样，再决定是否加分辨率或改源。

若选择矢量，确认使用端支持实际用到的文字、滤镜、裁切和外部引用；不要只验证设计软件能打开。项目可用 HTML/CSS 绘制边框、焦点或简单形状时，可以继续用代码源，交付其设计值和适用状态。

文字通常留给界面排版，以便本地化和字体回退；确实需要把字做进画面时，明确适用语言和更新成本。九宫切片、图集、压缩和多倍率导出只有在消费端确有支持与需求时启用，并记录切片边界或打包设置。

## 命名、版本与导出

**必须保持**资产身份、引用关系和导出来源可追踪。名称变化后检查消费者；替换正在使用的资源时保留可回退版本。不要修改逻辑类型标识来配合一个新的视觉文件名。

**建议约定**稳定语义标识，例如 `ui.action.repair`；文件名可用 `ui_action_repair_default.png`。项目用 Git 管理时，修订由提交记录表达；离线交付时可用 `v003` 区分包。不要同时使用多套互不关联的「最终版」编号。

导出说明应让接手者用相同源与工具设置重做这批文件：工具及版本、源修订、导出操作或已有命令、输出路径、格式与参数、必要依赖、实际输出结果。不能自动复现的手工步骤就逐步记下；不要声称存在尚未实现的导出脚本。

产物预算由目标场景测量后确定。记录磁盘大小只能证明传输量的一部分；解码后的纹理占用、同时显示数量与帧耗时需要在客户端观察，不能靠文件压缩比推断达标。
