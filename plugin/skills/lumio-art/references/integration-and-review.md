# 客户端接入、显示排障与验收

用于从「文件已经做好」推进到「目标场景确实使用了正确文件」。仅做美术评审时执行视觉部分；需要接入时再运行项目已有客户端流程。

## 定位一个真实消费点

先按 [项目布局](../../lumio-development/references/project-layout.md) 找到实际游戏内容和客户端宿主，再看 [入门说明](../../lumio-development/references/getting-started.md) 的可用运行路径。不要为换一个资源重建整个项目或假设已经有公开部署环境。

记录当前客户端版本、资产版本、进入目标画面的步骤和已工作的参考资源。找到代码或配置中真正引用文件的位置：页面图片、样式资源、Canvas 绘制、模型加载器、地形表现映射等均可能存在，但不是每个宿主都提供全部入口。

把接入状态写清：

| 状态 | 可报告的结论 | 下一步 |
|---|---|---|
| 已找到加载入口并成功显示样品 | 这一入口、这一格式与参数组合已验证 | 记录设置，扩展到本次资产 |
| 有格式说明或代码，未成功跑通 | 有候选接入方式，集成未验证 | 用一个最小文件验证并保存结果 |
| 只有概念图、实体声明或设计提案 | 设计或数据职责已明确 | 列消费缺口；不宣布导入管线可用 |
| 环境、工具或授权资源缺失 | 本次无法验证对应部分 | 完成交付中可独立进行的部分，交代复验条件 |

## 最小接入流程

1. **保留基准**：记录改动前的资源引用、客户端画面与相关运行输出。确保可恢复已知正常版本。
2. **替换一个样品**：按现有路径接入导出物，确认构建输出或静态目录实际包含它。路径与文件名大小写按消费端核对。
3. **确认加载的是本版**：查看请求地址、响应结果、内容类型及实际文件；检查缓存或旧构建产物。页面无报错不等于新资产已加载。
4. **验证表现参数**：实际大小、缩放、透明边、裁切、色彩、层级；世界资产再看坐标、朝向、接地与遮挡。仅检查本入口支持的参数。
5. **验证状态与生命周期**：切换适用状态，离开再进入界面或场景，触发重复显示与结束；确保旧图、旧对象或效果不会残留。
6. **记录结果后扩量**：把成功的源版本、导出设置和消费位置关联起来。失败时保留最小复现及证据，修正原因后再扩展。

运行浏览器示例应使用其文档规定的服务方式，不能默认双击 HTML 即可。示例点位页缺少 WASM 发布产物时可能仍显示空画布；这类情况先核对宿主和数据来源，不能仅靠换图片排查。通用环境与运行故障见 [诊断说明](../../lumio-development/references/diagnostics.md)。

## 显示问题按证据定位

| 现象 | 先检查什么 | 交给谁或怎样继续 |
|---|---|---|
| 资源不出现 | 文件是否进输出目录，请求是否成功，路径大小写，加载器是否处理该格式 | 先修打包或引用；没有消费者则报告能力缺口 |
| 仍显示旧版 | 当前页面或构建版本、实际响应文件、缓存行为 | 用新旧文件证据定位，不通过随机改名长期掩盖缓存问题 |
| 小图发糊 | 真实显示大小、文件像素、缩放次数与采样方式 | 用一张基准图比较，再改导出或显示设置 |
| 透明边发黑、发白或裁切 | 导出背景、透明处理、消费端混合方式、图集边距是否适用 | 用深浅背景复现后对齐源与消费设置 |
| 色彩偏离设计 | 文件与宿主的色彩处理、着色参数、灯光或后处理是否存在 | 在同一客户端作对照，避免来回盲改源色 |
| 模型旋转、悬空或比例不对 | 源单位、轴、原点、挂点、导出转换与消费变换 | 先用尺度标记样件定位，不用动画补偿导入错误 |
| UI 状态不对 | 程序状态、事件到达、样式覆盖、资源映射 | 视觉资源与状态逻辑分别检查，不把逻辑错误当作重绘任务 |
| 效果残留或重复 | 创建与结束条件、场景卸载、资源释放、重复触发策略 | 接入方检查生命周期，美术核对预期表现 |
| 换素材后掉帧 | 同场景前后帧耗时、加载时刻、资源占用和同时显示数量 | 对照项目预算找变化来源，按测量结果调整 |

排障报告包含可复现步骤、资产与客户端版本、目标设备及浏览器、预期与实际、最小截图或日志。截图不要包含账号、票据或个人信息；无关私有素材不随问题包外发。

## 视觉验收与集成验收分别给结论

**视觉检查**针对简报与项目规范：

- 实际显示大小和常见镜头下能辨认玩家需要的信息，同组资产的轮廓、重心与留白一致。
- 正常、禁用、等待等适用状态没有歧义；需要依靠颜色传达的信息还有项目要求的其他提示。
- 深浅背景、相邻资产、文字长度和支持的缩放下没有裁切、不可读或明显边缘问题。
- 世界表现的轮廓、遮挡与语义不误导可通行性、交互位置或危险区域。

**集成检查**针对实际消费者：

- 正确文件进入构建或服务输出，版本与来源可追溯，目标画面确实使用了本次资产。
- 状态、跟随、朝向、创建与结束符合接入约定；适用的进出场景与重复操作没有残留。
- 当前目标浏览器和设备运行无本次资源引入的加载或渲染错误。
- 需要性能验收时，在约定设备、视口和场景下记录可比较测量；没有预算或未测就不写「性能通过」。

来源记录、可编辑源、导出步骤和回退位置属于交付完整性检查。视觉通过不能覆盖集成失败，环境阻塞也不能写成通过；可以交付已完成部分并明确余项。

## 一次修改意见与交付写法

修改意见要让接手者知道改哪里以及如何判断已修复。例如：

> `ui.action.repair` v003，维修面板禁用态；实际显示大小下，轮廓与浅色背景合并，动作文字仍清楚。建议先调整禁用态的边界处理，保持基础符号不变。复验：在该面板两种背景下对比默认与禁用态，确认符号仍可辨识。集成映射本轮未改。

交付记录可以很短，但每个结论都应有实际依据：

> **交付**：资产标识及修订，源文件、导出物、来源记录位置。
>
> **接入**：实际消费入口、客户端版本、可回退引用。
>
> **视觉**：已检查的场景和结果，证据位置。
>
> **集成**：执行的步骤或命令、结果；未运行时明确「未验证」。
>
> **余项**：缺失能力或未满足条件、影响范围、接手方的下一步。

只提出设计建议时标为建议，不擅自修改项目风格规则。复验针对问题本身和受影响场景，不机械增加与本次改动无关的验收流程。
