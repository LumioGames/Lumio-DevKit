# 客户端接入、显示排障与验收

这页把“文件已生成”推进到“目标客户端确实使用了它”。视觉评审和集成验证分别给结论。

## 最小接入流程

1. 记录客户端、游戏和资产版本，保留一个已工作的相邻资源作基准。
2. 对方块资源先运行 `node Tools/check-block-assets.mjs`，再确认描述 JSON、贴图和 `pack.json` 都进入发布目录。
3. 构建 WebGL2 spectator bundle，经 HTTP(S) 服务发布的 `wwwroot` 打开目标页面；不要用 `file:` 或源码目录冒充发布物。
4. 在 Console/Network 和实际画面同时确认请求路径、内容类型、透明度、缩放、裁切和缺资源警告。
5. 切换适用状态、离开再进入场景、重复触发创建/结束，确认旧对象和效果都释放。
6. 记录命令、页面/场景、截图或日志；未运行的部分写“集成未验证”。

## 现象和证据

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 方块不出现 | 描述 JSON、`pack.json`、Network 请求和贴图大小 | 先跑资产检查器，再修源或消费映射 |
| 仍显示旧版 | 发布目录、缓存、实际响应文件和提交号 | 清理本次构建输出后复验，不用随机改名长期掩盖 |
| 透明边或镂空错误 | PNG alpha、WebGL2 混合和相邻面 | 在深浅背景各复现一次，保存最小截图 |
| 模型悬空/旋转错误 | 单位、轴、原点、挂点和消费变换 | 用带尺度标记的样件定位，不靠动画补偿逻辑位置 |
| 资源加载失败 | `_framework/`、WASM、HTTP 状态和页面导入映射 | 记录缺运行环境或能力缺口，不把空画布算通过 |
| 换素材掉帧 | 同一场景的帧耗时、并发数量和解码时间 | 用测量结果调预算；没有测量就不写性能通过 |

## 交接记录

交付至少包含：资产 ID 与版本、源和导出路径、`check-block-assets.mjs` 结果、WebGL2 页面/场景、来源许可、已验证项目和未验证项目。视觉检查不能覆盖接入失败；接入环境缺失时交清复验条件。
