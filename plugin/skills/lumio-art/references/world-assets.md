# 体素、材质、实体模型与世界表现

用于场景套件、地形表面、可动对象、角色或特效的制作与交接。先确定对象在世界中的职责，再决定如何表现；一个建模文件的扩展名不能决定它是体素还是实体。

## 按用途划分责任

| 要做的东西 | 世界职责 | 美术交付重点 |
|---|---|---|
| 静态、不需要独立服务器业务逻辑的地形和场景占格 | 体素 | 形状与尺度、表面识别、拼接与边界 |
| 移动角色、可拾取物或需要服务器逻辑的对象 | 实体 | 外观、方向、尺度、状态表现及必要动画说明 |
| 固定占格且有库存等业务逻辑的容器 | 占格部分为体素，逻辑部分为实体 | 分别交占格视觉和开关等状态外观，关联交给玩法实现 |
| 仅客户端需要的世界光环、火花或装饰性动态表现 | Local Entity | 出现与结束条件、跟随关系、视觉参数及清理方式 |
| HUD 图标、面板背景、字体 | 客户端界面资源 | 由实际界面消费；不把每张图片等同于世界实体 |

体素与实体是世界模型的分类；模型、图片、材质、动画是它们可能使用的表现资源。网页 DOM 控件不因此构成第三种世界对象。有关玩法状态和类型的开发工作见 [能力说明](../../lumio-development/references/capabilities.md)。

## 体素地形与表面

先确认项目体素尺寸、格子坐标、地形结构及可用的表现入口。美术需要交代可见表面如何区分地形、边缘与转角怎样拼接、远近观看是否容易误读；不要以绘图软件的像素数代替游戏世界尺寸。

「材质」要分清两种含义：

- **体素类型或玩法属性**：决定格子是什么，以及碰撞、可破坏性等行为。由已有类型与玩法配置管理。
- **表面外观**：颜色、纹理、粗糙感、明暗或其他已受支持的渲染参数。由消费端的表现映射决定。

交接时列「项目已定义类型或语义 → 外观资源 → 实际消费位置」。只能引用项目已有的类型标识，不编造通用材质编号或渲染字段。如果修改会让可通行区域看似阻挡，或让不可破坏表面看似可破坏，先在玩法场景检查语义一致性。

代表样品建议覆盖相邻表面、边角、边界与已支持的状态变化。使用贴图时看重复接缝和密度；使用颜色或程序化表面时看相邻类型的辨识。若宿主支持自由镜头，再检查俯仰与背面；没有支持的角度不列为已验证。

地图数据与美术源分开：地图快照承载世界内容，贴图或模型承载表现。当前示例的 `maps/sample.voxel` 是作者阶段生成的快照；它不证明外部体素编辑器文件可直接导入，也不证明给快照增加贴图字段会被渲染。改地图应使用项目实际可获得的作者工具，保留源布局与生成步骤；不手改快照内部结构来试配材质。

## 实体模型与动画

先让接入方指出一个已工作的模型或动画加载案例；只有类型声明或位姿输出时，先记录为「实体存在，模型消费尚未证明」。下面是需要对齐的信息，不是 Lumio 已内置的模型导入参数表：

| 对齐项 | 美术与接入方需要确认 |
|---|---|
| 尺度与坐标 | 世界单位、上方向、前方向、导出轴转换、实际大小 |
| 原点与接地 | 旋转中心、脚底或底座参考点、挂点与跟随对象 |
| 几何与外观 | 轮廓、网格层次、材质槽、依赖贴图，以及消费端支持的表达方式 |
| 动画（适用时） | 片段用途、循环与结束、切换时机、速度控制、骨骼或其他驱动是否受支持 |
| 玩法边界 | 可见轮廓与实际碰撞是否一致，攻击与交互范围由什么确定 |
| 生命周期 | 何时创建、切换外观、隐藏、销毁，加载失败时怎样表现 |

先制作含尺度标记的简单样件并放入实际场景；确认坐标、朝向和接地后，再做精细模型或成套动画。未确认消费者前，源文件可以完成，但不能声称某种模型格式、骨骼或材质已能进游戏。

模型位移、脚步和特效不能擅自写入权威位置或决定伤害时刻。若宿主提供表现变换与事件接口，接入其输出；需要改变逻辑运动或技能节奏时交玩法实现。视觉上不穿地的模型，也不证明碰撞或预测已经正确。

## 局部特效与动态装饰

将需求写为可观察的触发与结束条件，例如「交互确认后出现短暂标记，退出场景时释放」。说明是否跟随对象、是否遮挡关键 UI、重复触发时叠加还是替换，以及宿主当前支持的表现技术。

当前示例有 Local Entity 形式的火花声明；声明只证明其世界归属，不证明粒子、序列帧或 shader 管线已经提供。没有特效消费端时，可以交节奏说明、关键帧草图或可编辑源，并把接入状态写清。不要为完成美术任务自行引入新的同步消息、预测机制或服务器状态。

透明叠层、灯光、粒子数量与同屏并发的开销随具体渲染器和场景变化。先做项目代表场景的测量，再确定预算；不照搬其他引擎的模块开关或面数上限。

## 当前能力的检查方式

以下依据 2026-09-14 核对的实现范围。浏览器是当前客户端主线的工作起点，Unity / HybridCLR 相关旧规范不能直接作为首发导入步骤。已核对的点位示例通过 C# WASM 输出位置并由 Canvas 绘制圆点，这是最小表现链的证据；它不能代表完整体素画面、模型、材质或动画资产管线。是否包含该示例及其运行依赖，仍要检查实际取得的客户端分发。

按当前项目和所用发布版本重新查证：是否有加载入口、公开参数说明、可获得的工具与运行例子。缺其中一环时写明待补能力和最小验证，不臆造导入命令。后续支持增加后沿用新接口，本文不把当前最小示例限制成永久的渲染上限。

世界资产的验收步骤见 [接入与验收](integration-and-review.md)。
