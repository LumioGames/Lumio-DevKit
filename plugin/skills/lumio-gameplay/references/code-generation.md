# 代码生成与注册表

代码生成把 `Gameplay/` 的实体、组件、技能和效果声明变成两端可装载的注册表。Sample 没有单独的公开 `generate` CLI；当前消费路径是初始化 `Engine/` 后用 .NET 构建触发 SDK 的生成目标。

## 从声明到注册表

1. 在共享源码写声明。例如 `Gameplay/EntityTypes/BoxEntity.cs` 的 `[EntityType(Mode.CS)]`、`[BlockEntity]`、`[Has(typeof(BoxComponent))]`，以及 `Gameplay/Components/Box/BoxComponent.cs` 的 `[EcsComponent]` 和同步字段。
2. 把需要按端变化的实现放入同名 `.Server.cs` / `.Client.cs`。`Directory.Build.targets` 按 `LumioEcsSide` 排除另一端文件；同一套 `Gameplay/` 源码因此会编出 server 与 client 两个视图。
3. 确保 `Engine/` 子模块已取到目标发布物，然后从 Sample 根目录构建：

   ```bash
   git submodule update --init --depth 1 Engine
   dotnet build LumioSample.slnx
   ```

   `Directory.Build.targets` 让 SDK 的 ECS 生成保持启用；缺少 `Engine/` 时构建会报告 `LUMIO_SDK_UNRESOLVED`，不能用同级私有仓或全局包替代。
4. 检查 `Gameplay/generated/server/` 与 `Gameplay/generated/client/` 的结果。典型输出包括 `Lumio.Sample.Gameplay.Registry.g.cs`、实体的 `*.Template.g.cs`、组件绑定文件、`GeneratedAbilityRegistry.g.cs` 和 `GeneratedEffectRegistry.g.cs`。
5. 用生成结果核对声明真的接入：`GeneratedRegistry.WorldEntityType` 指向 `WorldEntity`，`BlockEntityTypes` 包含 `BoxEntity` 和 `VeinEntity`，`GeneratedAbilityRegistry.RegisterAll()` 登记 `MoveAbility`、`MineAbility`、`PickupAbility`，效果注册表返回 `PickupOreEffect` 的类型号 `10`。这些文件带 `<auto-generated/>`，只能改声明后重新构建，不能手改。

## 生成结果的用途

- `GeneratedRegistry` 提供实体创建、组件编号、RPC 映射和系统描述；它是宿主装载玩法的入口。
- `GeneratedAbilityRegistry` 把技能类型和稳定 ID 交给 `AbilityTypeCatalog`；`GeneratedEffectRegistry` 提供效果类型号查找。
- `generated/server` 与 `generated/client` 必须来自同一提交的声明。不要把 server 生成物复制到 client 目录，也不要提交只在一端生成的临时文件。

配置表的 Reader 是另一条生成链：按 [配置表技能](../../lumio-config/SKILL.md) 的说明使用项目已有脚本；本页只覆盖 Gameplay 注册表。Sample 中也没有一个可供开发者直接调用的独立 ECS `generate` 命令，不能从生成文件名倒推命令参数。
