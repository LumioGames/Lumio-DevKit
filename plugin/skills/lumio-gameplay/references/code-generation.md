# 代码生成与注册表

代码生成把 `Gameplay/` 的实体、组件、技能和效果声明接到引擎可装载的注册表，免去手工维护两端编号和分发代码。

## 给箱子加组件后会发生什么

1. `Gameplay/EntityTypes/BoxEntity.cs` 用 `[EntityType(Mode.CS)]`、`[BlockEntity]` 和 `[Has(typeof(BoxComponent))]` 声明箱子类型。
2. `Gameplay/Components/Box/BoxComponent.cs` 用 `[EcsComponent]`、同步字段及 `[Persist]` 声明状态；服务器方法放在 `Gameplay/Components/Box/BoxComponent.Server.cs`。
3. 分别构建服务器与客户端，生成器读取当前端的声明，输出实体模板、组件绑定、RPC（远程过程调用）分发、技能与效果类型号等代码。
4. 查看两端 `BoxEntity.Template.g.cs` 是否包含 `BoxComponent`，以及 `Lumio.Sample.Gameplay.Registry.g.cs` 的 `BlockEntityTypes` 是否包含 `BoxEntity`。此时再到运行中的宿主检查可见范围和开箱行为。

## 操作与命令

前提是已按 [入门](../../lumio-development/references/getting-started.md) 取得 `Engine/` 子模块和匹配的 .NET SDK。以下命令均从 Sample 仓根执行；引擎初始化命令来自 `Directory.Build.targets`，两次构建命令来自 [`README.md`](https://github.com/LumioGames/LumioSample/blob/f98322c2eec8f83b5caf07aa2ad15d9c55b6f8fb/README.md) 与 `.github/workflows/tour.yml`，提交 `f98322c2eec8f83b5caf07aa2ad15d9c55b6f8fb`，许可证 Apache-2.0：

```sh
git submodule update --init --depth 1 Engine
dotnet build LumioSample.slnx
dotnet build Gameplay/Lumio.Sample.Gameplay.csproj -p:LumioEcsSide=client
```

第一条补齐发布物；第二条按默认服务器端构建；第三条明确构建客户端端。`dotnet build LumioSample.slnx` 不能替代客户端这次构建。

SDK 的 `build/Lumio.Engine.SDK.props` 默认设置 `LumioEcsGenerate=true`；`build/Lumio.Engine.SDK.targets` 的 `LumioGenerateDeclarations` 在编译前运行包内生成器。Sample 的 `Directory.Build.targets` 再按 `LumioEcsSide` 排除另一端文件。游戏工程在 `Gameplay/Lumio.Sample.Gameplay.csproj`，输出分别进入 `Gameplay/generated/server/` 与 `Gameplay/generated/client/`。Sample 的日常入口就是构建，没有另一个需要手工运行的游戏仓 `generate` 脚本。

## 检查生成结果

| 文件或类型 | 应看到什么 |
| --- | --- |
| `Gameplay/generated/server/Lumio.Sample.Gameplay.Registry.g.cs` 与客户端同名文件 | `GeneratedRegistry.WorldEntityType` 指向 `WorldEntity`；`DeclaredTickRateHz` 为 `20`；`BlockEntityTypes` 包含 `BoxEntity`、`VeinEntity`。 |
| 两端的 `BoxEntity.Template.g.cs`、`BoxComponent.g.cs` | 模板创建组件，组件生成字段绑定、同步、存档等实现。 |
| `Gameplay/generated/server/GeneratedAbilityRegistry.g.cs` 与客户端同名文件 | `RegisterAll()` 登记 `MoveAbility`、`MineAbility`、`PickupAbility`，类型号分别为 `1`、`2`、`3`。 |
| `Gameplay/generated/server/GeneratedEffectRegistry.g.cs` 与客户端同名文件 | `TypeIdOf` 将 `PickupOreEffect` 对应到 `10`。实际登记在 `Gameplay/SampleGameplay.cs` 的 `RegisterCatalog` 中调用 `PickupOreEffect.Register()` 完成。 |
| `Gameplay/generated/client/MiningSparkEntity.Template.g.cs` | 本地实体只在客户端生成；服务器目录不应出现这个模板。 |

生成文件带 `<auto-generated/>`，应修改声明后重新构建，不手改输出，也不把服务器生成物复制到客户端。两端要来自同一份声明。新增技能与效果后，按 [GAS 技能](gas-abilities.md) 检查登记与调用，不能只看文件名。

缺少 `Engine/` 会报 `LUMIO_SDK_UNRESOLVED`；先补子模块。声明变化没出现在生成结果时，检查当前端、`LumioEcsGenerate` 与构建错误；只有服务器生成物更新时补跑客户端构建。配置表的 Reader（读取导出表的生成类型）属于另一条链，见 [配置表技能](../../lumio-config/SKILL.md)。
