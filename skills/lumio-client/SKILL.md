# Lumio 客户端开发

帮助开发者把游戏的客户端程序集交给现有 Host，提交输入并观察服务器结果。开始时确认用户要做的是 Bot 场景、浏览器表现还是游戏客户端代码，读取实际分发物版本和游戏项目文件。

通用环境与 SDK 取得方式见 [Lumio 开发](../lumio-development/SKILL.md)。这里不要求开发者取得引擎源码，也不假设存在已发布的客户端 NuGet 包、Unity 插件或编辑器。

## 执行顺序

1. 核对 SDK、客户端 Host、Native 二进制与游戏程序集是否来自兼容发布；缺哪个产物就明确指出。
2. 编译客户端侧声明，确认生成注册表可由宿主装载。真实连接必须有平台签发的房间准入票。
3. 先跑一个 Bot、一条可用命令。检查输入接收结果、实际上行、权威回执和表现结果，再扩大范围。
4. 汇报执行的命令、退出码、证据路径与尚未完成的步骤；未运行的宿主不能写成验收通过。

## 开发约束

- 服务器持有权威状态；客户端表现和 Local Entity 不充当权威结果。
- 使用生成的客户端接口和 Host 提供的输入出口；不要自拼 Gameplay wire、调用服务端入站分发器或建立另一套预测实现。
- 每次操作保留明确的接受或拒绝原因。普通操作拒绝应结束该次操作，不能主动销毁世界；若现有 SDK 因拒绝导致会话或世界失败，记录为缺陷。
- 不自动重发操作、重建会话或恢复存档。部分现有宿主有自动取票行为，先确认与用户要求一致；见排障文档的限制。
- `started`、`connected`、`admitted` 是三个不同阶段。上行成功也不等于服务器已经应用。
- 当前示例与 Host 有未接通能力；按实际词表的 `Available` / `BlockedReason` 判断，不按类名存在与否猜测。
