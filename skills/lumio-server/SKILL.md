# Lumio 服务端开发与运行

把已编译的服务器玩法和内容交给 `lumio-ds`，核实配置、真实 Ready、客户端准入与一次业务操作。先确认是本地首次运行、现有服务排障还是发布操作，保留用户选择的范围。

SDK 和通用项目结构见 [Lumio 开发](../lumio-development/SKILL.md)。公开教程从分发物开始；缺少 SDK、DS 或平台服务就明确列为缺失前置，不要求用户访问私有实现仓。

## 执行顺序

1. 核对分发清单、SDK/Host/Gameplay 版本及平台分配的房间身份。
2. 使用分发包模板填写配置，运行 `--check-config`；它不验证程序集、Native 或配表实际可用。
3. 明确持久化目录的用途后启动本地实例，等待真实 `DS_READY`，再用匹配准入票连接一个客户端。
4. 只做一次目标操作，分别核对操作结果、权威状态和下行；需要保存/重启验证时单独安排。
5. 汇报执行命令、日志路径、退出状态和能力限制，不把文件存在、进程存活或 fixture 通过写成生产验收。

## 语义与范围

- 玩法写在游戏程序集里，网络和进程生命周期交给现有 Host；不在网络回调中推进世界，不添加引擎替身。
- 普通操作拒绝必须清楚反馈，不主动杀世界；若当前运行路径升级为世界失败，记录为缺陷。
- 不自动重试有副作用的命令、重启进程或恢复世界。现有 DS 在启动时自动读取检查点，且部分错误处理仍有局限，见排障参考。
- 存档损坏或版本不符时保留原始目录与首次错误；不删数据、不拼接不同检查点来制造成功。
- Hello、免认证 observer 与 test harness 是有限验证入口；正式连接使用平台房间票和 `lumio-ds`。
- 需要公网运行时使用已有受控 WSS 边缘与准入配置，完成具体部署准备后再按授权范围执行。
